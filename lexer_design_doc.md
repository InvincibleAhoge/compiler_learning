# 词法分析器（Lexer）

------------------------------------------------------------------------

# 一、什么是词法分析器（Lexer）

在任何编译器或代码解析工具中，第一步都是：

> 把原始文本拆分成有结构的最小单位

这个过程叫：

**词法分析（Lexical Analysis）**

拆出来的最小单位叫：

**Token（词法单元）**

例如：

    happy | adj. | very good mood

会被拆成：

    Text("happy")
    Pipe("|")
    Text("adj.")
    Pipe("|")
    Text("very good mood")
    EndOfLine

也就是说：

    字符串 → Token序列

后续 parser（语法分析器）就是基于这些 token 工作的。

------------------------------------------------------------------------

# 二、本项目中的词典文件格式（.voc）

当前项目解析的文件格式为：

    word | pos | meaning | example

示例：

    happy | adj. | very good mood | She feels happy today.

字段说明：

  字段      含义
--------- --------------
  word      单词
  pos       词性
  meaning   释义
  example   例句（可选）

字段之间使用：

    |

作为分隔符。

------------------------------------------------------------------------

# 三、当前 lexer 支持识别的 Token 类型

定义如下：

``` cpp
enum class Kind {
    Text,
    Pipe,
    EndOfLine,
    Invalid
};
```

含义如下：

  类型        说明
----------- ------------
  Text        普通文本
  Pipe        分隔符 `|`
  EndOfLine   行结束
  Invalid     非法内容

------------------------------------------------------------------------

# 四、Token 的数据结构设计

``` cpp
struct Token {
    Kind kind;
    size_t start;
    size_t length;
    size_t line_no;
};
```

Token **不存储字符串内容**，只记录位置。

------------------------------------------------------------------------

# 五、Lexer 扫描流程

扫描顺序如下：

### Step 1：跳过前导空格

        happy

忽略前导空格

------------------------------------------------------------------------

### Step 2：跳过前导符号

支持忽略：

    +
    -

------------------------------------------------------------------------

### Step 3：逐字符扫描

识别以下情况：

  情况           生成 Token
-------------- ------------
  遇到 `|`       Pipe
  遇到普通文本   Text
  行尾           EndOfLine
  非法结构       Invalid

------------------------------------------------------------------------

# 六、Lexer 调用方式

统一接口：

``` cpp
auto tokens = lexer::tokenize(line, line_no);
```

返回：

    vector<Token>

示例：

输入：

    happy | adj. | very good mood

输出：

    Text
    Pipe
    Text
    Pipe
    Text
    EndOfLine

------------------------------------------------------------------------

# 七、test.voc 文件的作用

该文件用于测试 parser：

包含：

-   正常数据
-   缺失字段
-   非法结构

示例：

缺少 word：

    | v. | to move quickly

缺少 pos：

    run | | to move quickly

缺少 meaning：

    sad | adj. |

用于验证错误处理能力

------------------------------------------------------------------------

# 八、现实编译器中的词法分析器

例如 C 语言代码：

    int a = 3;

词法分析输出：

    Keyword(int)
    Identifier(a)
    Operator(=)
    Number(3)
    Semicolon

本项目 lexer 与真实编译器 lexer 原理一致，只是输入不同。

# 九、项目代码风格说明（团队规范）

本项目采用：

**弱 OOP 风格**

即：

    enum + struct + function

而不是：

    class Token
    class PipeToken
    class TextToken

原因：

  优点       说明
---------- ------------------------
  简单       易理解
  高效       无虚函数
  工业标准   编译器通用写法
  易扩展     适合 parser / AST / IR
